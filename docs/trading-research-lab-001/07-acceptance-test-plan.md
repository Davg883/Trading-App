# 07 — Acceptance-test plan

Tests are hermetic: no live market data, no paid models, no broker calls. The exceptions are the explicitly marked staging tests, which use the Trading 212 **demo** account and a non-production Convex deployment.

| ID | Requirement | Test | Pass criterion |
|---|---|---|---|
| A1 | 1 Universe | Register an experiment; attempt to add a symbol mid-experiment | Refused; a new version is required |
| A2 | 2 Timestamped inputs | Ingest fixture bars, filings and news with event, published and received times | All four times stored; rows missing a receipt time are rejected |
| A3 | 11 Point-in-time | Decision at T with an item published before T but received after T | Item excluded and counted; decision digest unchanged by the late item |
| A4 | 3 Detection | Feature engine on fixed fixtures | Deterministic outputs equal golden values; no access to bars after T (asserted by a spy) |
| A5 | 4 Decisions | Each strategy on fixture scenarios | Correct TRADE / WAIT / REJECT with reason codes and evidence ids; a model provider failure or abstention gives WAIT |
| A6 | 5 Three strategies | Strategy versions are hashed separately | Changing one threshold changes only that strategy's version hash |
| A7 | 6 Record before outcome | Attempt to write a decision whose `decidedAtMs` is after the first outcome bar it depends on | Refused |
| A8 | 7 Deterministic sizing and costs | Golden cases, including the notional cap, minimum order, gap through stop, and FX | Exact quantities, effective R and cost components |
| A9 | 10 Metrics | Fixture trade set | Net P&L, drawdown, win rate, expectancy (with bootstrap CI), profit factor, costs, excess vs QQQ equal reference values computed independently in the test |
| A10 | 9 Human review | No order intent before approval; for each of approve, amend, reject, defer and convert WAIT to TRADE, the event is journaled with reviewer, time and latency; an amendment that raises risk above the proposal or a limit is refused | Each journal entry is present; originals unchanged; only approve and amend produce intents |
| A11 | 12 Duplicates and fills | Two simultaneous intents for one decision; a retried intent; an ambiguous broker response (mocked) | Exactly one order claim; retry refused; ambiguous goes to `unknown` and blocks the symbol until reconciled; intended vs model vs demo fill recorded |
| A12 | 8 Demo only | Source and **built bundle** contain no live base URL; client construction with a non-demo environment throws; the research app's boundary suite still passes | All pass. **Staging:** a demo order round-trip on the Trading 212 demo account |
| A13 | 13 Limits and halts | Daily, weekly and drawdown loss limits; exposure and cluster caps; data staleness; kill switch | Each blocks new entries inside the claim mutation, not only in the UI |
| A14 | 14 Journal | Recompute the hash chain from an export; tamper with one exported entry | Verification passes untampered and fails at the tampered sequence; there is no update or delete API |
| A15 | Benchmark | QQQ GBP-adjusted per-trade and portfolio benchmark on fixtures | Matches an independent calculation, including the FX convention |
| A16 | Security | Unsigned, expired, altered or replayed intents; secret reuse | All refused |
| A17 | Statistics guard | The report generator after L4 | Report template contains no "profitable" or "beats" language unless the pre-registered L5 criteria are met (lint-style check) |
| A18 | NVIDIA case | Registration before release; post-release decision references it; attempt to edit the pre-release entry | Edit impossible; correction creates a new entry; both are reported |
| A19 | P4 D3, D6 Signal immutability | Journal a TRADE; apply every kind of review event; recompute R1 | R1 results and the decision's `entrySha256` are byte-identical before and after; the decision is journaled before it is visible in the queue |
| A20 | P4 D5 Expiry and missed opportunities | Leave a decision unreviewed past expiry; then attempt approval; approve one whose limit never fills | `review_expired` recorded and approval refused; `order_unfilled` recorded; both appear in R1 and as no trade in R2 |
| A21 | P4 D1, D2 No automatic execution | Static check that no scheduled function, timer or configuration value issues an order intent; time-advance test with a pending decision and no review | No intent is created; the paper service refuses an intent without a matching approval event |
| A22 | P4 D4 Two records | Fixture set with approvals, rejections, amendments, delays and misses | R1 and R2 metrics match an independent calculation; the attribution terms sum to R1 − R2 |
| A23 | Entry-authorisation expiry | Golden cases for each strategy and candidate type, including DST changes and an early close; approval one millisecond after expiry; reviewer attempt to extend; a partly filled entry at expiry; a position open at expiry | Expiry equals the rule in `01` §8.1; late approval refused and no intent issued; no extension API exists; the unfilled remainder is cancelled; open positions follow only their exit rules |
| A24 | Invalidated, blocked, unfilled | **Invalidated:** S1 price reaches the invalidation level; a verified source correction or retraction; a registered deterministic contradiction rule (fixture rule). **Blocked:** stale price, unverified data, exchange halt and exhausted risk limit, for each of S1, S2 and S3; then the condition clears before expiry; then it does not. **Unfilled:** price above the buy limit until expiry. Also: no entry range registered; a price move alone on S2 and S3 | Exactly one final outcome per decision, with the correct reason code. `setup_invalidated` is permanent and a later opportunity has a new `decisionId`. A block lifts when the condition clears but the expiry is unchanged; a block never produces `setup_invalidated`. Price above the limit ends as `order_unfilled`. No entry-range or price-threshold invalidation exists. Filled positions are unaffected |
| A25 | Pre-market classification | `decidedAtMs` either side of 09:30 New York; an exchange holiday; an exceptional late opening; DST change | Classification follows the exchange calendar; S2 10:00 and S3 11:00 expiries are unchanged; a candidate whose session opens at or after its expiry expires unfilled |
| A26 | Thesis review | A later AI-classified expectation-lowering item with no contradiction rule satisfied; reviewer confirms; reviewer rejects; no reviewer decision before expiry; reviewer record without evidence | `REVIEW_REQUIRED` raised and the entry blocked; the AI classification alone never invalidates. Confirm gives `setup_invalidated`. Reject lifts the block but restores no approval; an order needs a fresh approval before the unchanged expiry. The shadow record stays blocked while the review is unresolved and is unchanged by the reviewer's decision. No decision ends as `entry_blocked`. A record without evidence, timestamp and decision is refused. The original decision's `entrySha256` is unchanged throughout |
| A27 | Shadow portfolio realism | Replay fixtures in which R1 would gain from: a fill during a halt; a fill outside the session window; a fill on stale data; an entry beyond a risk limit; a fill after expiry; a fill larger than the bar's volume allows; a fill recomputed from a corrected or later bar | Every such fill is refused or classified as in R2. R1 fills are journaled forward and never recomputed. R1 reads no approval, rejection, amendment or thesis-review decision |
| A28 | Counterfactual signal analysis | Decisions blocked by a thesis review with each review result; compute the counterfactual; then generate the headline reports | Counterfactual results exist, grouped by review result and labelled hypothetical. R1 and R2 returns, equity curves, risk state and statistical tests are byte-identical with and without the analysis. The analysis has no write path to decisions, review events or order intents |
| A29 | Liquidity and fill eligibility | Bars with: high volume but no quote; spread above the maximum; an auction print; a halt; a stale or flagged price; an order larger than 1% of eligible volume; the same fixtures in the R2 model-ledger simulation | No fill from volume alone. A fill needs valid price, spread, session and fill-assumption checks. Fills never exceed 1% of eligible volume per bar; the remainder carries forward and is unfilled at expiry. R1 and the R2 simulation give identical results on identical inputs |
| A30 | Source corrections and lifted blocks | A correction authenticated to the licensed publisher; one authenticated to the issuer; an unauthenticated correction claim; a correction without timestamps. A block that clears before expiry and one that clears after. A rejected invalidation after the earlier approval's order was cancelled, before and after expiry | Only authenticated corrections with evidence and timestamps invalidate directly; the unauthenticated claim does not. A cleared block allows entry only before the unchanged expiry. A rejected invalidation never restores an approval; a new approval is required and is refused after expiry |

**Staging tests (owner-approved, non-production)**, mapped to the requirements above:
- A12: a demo order round trip;
- A11 against the real demo API (once);
- latency measurement over 10 sessions (`03` §3);
- concurrency of intent claims against a real Convex deployment.

**Exit criteria for each phase** are listed in `01` §10.
